Rated matchmaking and the round loop

Playtest

Fair matches when few people are online. Wait too long for a close rating and nobody plays; match anyone and new players get flattened.

Built
The search range starts at ±100 and widens 40 a second. The longest-waiting player anchors it, the closest ratings go first, a snake draft balances the teams, and bots take empty seats after 8 s. Ratings move by Elo.
Tested
Unit tests: a lone player gets bots, eight close players match at once into even teams, a far-off rating waits for the range to reach it, Elo moves by the size of the upset. Playtested from a solo queue through a full round to results.

Bots that think as a team

Playtest

Seat-filling bots have to be worth playing against: not a pack chasing the same orb, and not frozen when plans change mid-chase.

Built
A reactive behaviour tree per bot, re-checked from the top 8 times a second, so a bump interrupts a chase at once and the cut-off action cleans up. Above them, a squad director hands out Hunter, Escort, Collector and Runner roles from the state of the match, but never sends the whole team hunting.
Tested
Unit tests for branch priority, interrupts and cooldowns. In playtests each bot's label showed its live branch, and tuning took a full round from about 100 points down to 29.

03 / 04

Pip, an NPC who trades and haggles

Playtest

An NPC trader is the easiest way to dupe a game, because NPC code usually skips the rules players follow.

Built
Pip is an ordinary trade party: the same code path as a player, so he can't do anything a player couldn't. He values offers by rarity, pays 50% more for what he's after this rotation, keeps a cut, and counters with cosmetics you don't own yet. Haggling odds fall each try and depend on his mood, and regulars get a better deal.
Tested
In a playtest he took 50 in shards and gave 35 back (his 30% cut), and refused a haggle. The first version offered a halo the player already owned; now he never offers a duplicate.

DASH, a route-finding assistant

Every road keeps its two real ends, so roads at different heights (the highway runs 26 studs up) join into a 3D graph. DASH plans from wherever you are, calls the turns and keeps quiet on straight crossings.

  • Tested: on a route with 12 crossings (8 straight), DASH made 6 turn calls plus the street call, and said nothing at the straight ones.

Saves that survive server hops

Each visit writes its own lock id when it loads, and only saves while it still holds the lock, so a quick server hop can't load stale data. Data that never loaded is never saved, so an outage can't wipe anyone. Failed loads retry while the player keeps playing.

The lock check inside the save 
store:UpdateAsync(key(player), function(old)
	if type(old) == "table" and heldByOther(old.Lock, session) then
		lost = "other"
		return nil -- leave the newer save alone
	end
	return data
end)
How the script worksParcelService.luau · server
  1. Give

    The server picks one of the 12 types. Every box looks the same, and the type never leaves the server, so a client can't peek or cheat its pay. Each type gets its own first-effect timer; Fragile and Bouncy wait for the first crash or bump instead.

  2. Tick

    One Heartbeat loop runs every parcel 10 times a second, each inside a pcall, so one broken parcel can't stop the rest.

  3. Track the box

    It's in your hands, on the passenger seat, lying loose or floating off. It moves to the seat when you drive and drops where you were if you die. It only counts as lost after half a second below the map, not one odd reading.

  4. Read the car

    It compares the car's velocity with the last tick. A big change is a bump; losing 18 studs/s of speed in one tick is a crash.

  5. Run the effect

    One branch per type: Fragile cuts the pay 20% per crash (down to a floor), Heavy slows the car's speed and steering, Magnetic adds a real force toward the nearest post or pole, found in a 100-stud grid built once at start.

  6. Reveal

    The first time an effect kicks in, DASH reacts out loud, the box gets its type's markings and the map shows its icon.

  7. Pay at the door

    The job's pay is multiplied by the parcel's factor: Fragile's cuts, plus a bonus if a Ticking parcel arrives early or a cut if it's late.

The loop, and how a crash is spotted 
-- One loop for every parcel, ten times a second
RunService.Heartbeat:Connect(function(dt)
	accumulator += dt
	if accumulator < 0.1 then return end
	local step = accumulator
	accumulator = 0
	local now = os.clock()
	for _, p in parcels do
		local ok, err = pcall(tick, p, now, step)
		if not ok then warn("[ParcelService] " .. tostring(err)) end
	end
end)

-- Inside tick: compare the car's velocity with the last tick
local v = chassis.AssemblyLinearVelocity
if last then
	bump = (v - last).Magnitude >= P.BumpJolt
	local flatV, flatLast = Vector3.new(v.X, 0, v.Z), Vector3.new(last.X, 0, last.Z)
	crash = flatLast.Magnitude - flatV.Magnitude >= P.CrashJolt
end

A force, not a teleport

Pull the car toward the nearest lamppost, stronger the closer it is. Right on top of it the direction is undefined, so there's no pull rather than a NaN force.

local offset = Vector3.new(target.X - chassis.Position.X, 0, target.Z - chassis.Position.Z)
local strength = 1 - offset.Magnitude / P.MagnetRange
magnet.Force = if offset.Magnitude > 0.5
	then offset.Unit * chassis.AssemblyMass * P.MagnetPull * strength
	else Vector3.zero

Can this Seeker see you? 
local function canSee(root, target, ignore)
	local to = target.Position - root.Position
	if to.Magnitude > SIGHT_RANGE then return false end
	if to.Magnitude > 6 and root.CFrame.LookVector:Dot(to.Unit) < math.cos(FOV / 2) then
		return false
	end
	rayParams.FilterDescendantsInstances = ignore
	local hit = workspace:Raycast(root.Position + Vector3.new(0, 0.8, 0), to, rayParams)
	return hit == nil or hit.Instance:IsDescendantOf(target.Parent)
end

Request.OnServerInvoke = function(player, action, arg)
	local now = os.clock()
	if (lastRequest[player] or 0) > now - 0.15 then
		return false, "Slow down"
	end
	lastRequest[player] = now
	local p = profiles[player]
	local h = type(action) == "string" and handlers[action]
	if not (p and h) then
		return false, "Not ready"
	end
	return h(player, p, arg)
end

The questions hirers ask

How I work.

Studios check the same few things before they hire a scripter. Short answers, backed by the code above.

01

Server or client?

Anything worth something runs on the server: money, items, trades, ratings, cooldowns, damage. The client handles input, the camera, UI and whatever must feel instant.

02

Validating a purchase or trade

The client sends ids, nothing else. The server checks they exist, reads prices from its own config, checks balance and ownership, then grants. Trades also check the version each side accepted.

03

Not losing data

UpdateAsync with retries, autosave and BindToClose. A session lock stops two servers writing the same save, and data that never loaded is never saved.

04

Structure

Pure rule modules with tests (inventory, trades, matchmaking, behaviour trees), services that own their state, tunables in config, all strictly typed, in Rojo and Git.

05

Testing

Automated tests for the rules, then a Studio playtest of every feature, fixing what breaks. Studio-only hooks force a match, end it or drive a trade in seconds.

06

Handoff

Every file opens by saying what it owns, plus setup notes and a list of anything unfinished, so another scripter can pick it up.
